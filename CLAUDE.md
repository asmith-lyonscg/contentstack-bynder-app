# Sample files

When a change affects what this app saves or how a website renders it, update the matching sample in the same change.

- `samples/payload/sample-payload-large-hero.json`, `samples/payload/sample-payload-split-left-right.json`, and `samples/payload/sample-payload-custom.json` — one image sample payload each (`v`, `profile`, `assets`), not a Contentstack entry. Same Bynder files, different profile snapshots. The custom file uses `profile.id` `"custom"`. Match `persistedPayload` in `src/lib/settings.ts`. `profile.settings.desktop` and `profile.settings.mobile` are aspect-ratio strings. Leave out keys the app does not write: asset `aspectRatio`, `zoom`, a top-level `profileSettings`, and a `focalPoint` of `0.5` / `0.5`. Original size is `origWidth` and `origHeight`. Keep the existing sample assets unless the new shape needs an example they do not cover.
- `samples/payload/sample-payload-video.json` — one video with a separate mobile file. No crop, focal point, or DAT URL. Desktop `webImage.url` is the desktop file; `mobile` holds the mobile file identity and `webImage`. Desktop playback is `video` (`autoplay`, `muted`, `controls`, `loop`). When a different mobile file is assigned, mobile playback is `mobile.video` with the same keys. `differentMobileAsset` is true.
- `samples/payload/sample-payload-document.json` — one document. Identity, view `url`, `downloadUrl` (`url` with `download=true`), and `thumbnail` when the `/asset/{id}/{file}` preview can be built. No crop, DAT, alt, or mobile asset. The site chooses a thumbnail link, a text link, or a direct download.
- `samples/payload/sample-payload-url-image.json` — one manually linked image (`source: "url"`). Direct `webImage.url` only — no crop, focal point, DAT, or profile Fill. Desktop/mobile URLs, alt text, and measured `origWidth` / `origHeight` when known. `differentMobileAsset` is true when mobile has its own URL.
- `samples/payload/sample-payload-url-video.json` — one manually linked YouTube/Vimeo video (`source: "url"`). Normalized watch URL on `webImage.url`. No `video` / `mobile.video` playback object and no `alt` (videos never store alt). A Bynder file from `assets.deltafaucet.com/asset/{id}/…` is not this sample — it saves like Compact View (`sample-payload-video.json`).
- `samples/payload/sample-payload-url-document.json` — one manually linked document (`source: "url"`). File on `url` only (no Bynder `downloadUrl` / thumbnail derivation). Desktop/mobile URLs and alt text are supported.
- `samples/payload/sample-payload-url-mixed.json` — Bynder DAT desktop image plus a `source: "url"` mobile image. Shows that desktop and mobile do not have to come from the same place. Desktop still uses profile Fill / DAT; mobile uses `webImage.url` as-is.
- `samples/react-handler/sample-react-bynder-picture.tsx` — the sample React handler, a `<picture>` for the largeHero payload. It must keep using `buildBynderSources` for the DAT URLs. It passes a width list, and the height comes from the aspect ratio. Neither side may pass `maxDimension` (2000 when the snapshot omits it). largeHero and custom use the standard ladder. splitLeftRight passes a shorter list chosen for `sizes="40vw"`. Update this file when delivery, srcset steps, the max dimension, or the picture markup changes. Leave it alone for editor-only work.
- `samples/html-output/sample-html-large-hero.html`, `samples/html-output/sample-html-split-left-right.html`, and `samples/html-output/sample-html-custom.html` — one image `<picture>` each, with the URLs filled in for the matching payload. largeHero uses `sizes="100vw"`. splitLeftRight uses `sizes="40vw"`. custom uses `sizes="100vw"`. `img` `width` and `height` are that picture's desktop request size, not the CSS size. `sizes` is the displayed width. Keep the HTML comment at the top of each file. Write query separators as `&`, not `&amp;`. Regenerate a file whenever its payload or the picture markup changes. Do not add a full document around the picture.
- `samples/html-output/sample-html-video.html` — desktop and mobile `<video>` elements for the video payload. Each `src` is that viewport’s `webImage.url`. Map `controls`, `muted`, `autoplay`, and `loop` from that viewport’s playback object (`video` or `mobile.video`). Do not build a DAT URL.
- `samples/html-output/sample-html-document.html` — a linked thumbnail for the document payload. `href` is `url`. `downloadUrl` is available when the site wants a direct download. No `<picture>`.
- `samples/html-output/sample-html-url-image.html` — desktop and mobile `<img>` for the URL-image payload. Each `src` is that viewport’s `webImage.url`. No DAT or `<picture>`.
- `samples/html-output/sample-html-url-video.html` — desktop and mobile `<iframe>` embeds for the URL-video payload (YouTube / Vimeo). Do not use `<video src>` or DAT.
- `samples/html-output/sample-html-url-document.html` — desktop and mobile links for the URL-document payload. Each `href` is that viewport’s `url`.
- `samples/html-output/sample-html-url-mixed.html` — Bynder DAT desktop `<img>` (same ladder as largeHero desktop) plus a plain mobile `<img>` for the URL file. Do not run the mobile URL through DAT.
- `samples/payload/sample-payload-rte.json` — one JSON RTE `bynder` node. `attrs` is a largeHero field payload (`v`, `profile`, one asset) plus `display` (`width`, `height`, `alignment`, `caption`, `link`, `linkNewTab`, `inline`). Alt text stays on the asset.
- `samples/html-output/sample-html-rte.html` — the largeHero picture floated left at the display size, with the caption and link. The picture URLs stay the largeHero sample. Do not fork the URL math.

Do not fork the URL math into the sample.
